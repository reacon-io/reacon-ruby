## Getting Started

```ruby
require 'reacon-sdk'

config = Reacon::Configuration.new
config.api_key['X-API-Key'] = ENV.fetch('REACON_API_KEY')
config.timeout = 30 # Total network deadline in seconds, through body reads.
client = Reacon::ApiClient.new(config)

  counts = api.get_domain_counts('example.com', request_timeout: 10)
  puts counts.total
rescue Reacon::ApiError => error
  warn "HTTP #{error.status}, request #{error.request_id}, code #{error.error_code}"
  # error.response, headers, body and parsed_body preserve the server response.
rescue Reacon::RequestTimeoutError, Reacon::TransportError, Reacon::ResponseDecodeError => error
  warn "#{error.class}: #{error.message}"
end
```

`config.timeout` defaults to 30 seconds. `request_timeout:` overrides it for one
call; both require a finite positive number. The deadline includes request
construction, connection establishment, writes and complete response reads.
Buffered JSON decoding happens after network completion. The same deadline
applies to the CSV export helper. Long-lived verification streams have their
own idle/total timeout options.

The built-in Faraday Net::HTTP adapter closes each request's connection on
completion, timeout or interruption. It has no persistent connection pool and
needs no client shutdown call. Reuse the ApiClient for configuration and model
methods. Native Ruby interruption propagates unchanged: Ctrl-C or
`request_thread.raise(Interrupt)` interrupts a pending network call and unwinds
its connection cleanup. Rescue Interrupt only where your application chooses
to handle cancellation. No background SDK request continues after that unwind.

Requests do not follow redirects or retry automatically, including GETs that
may spend credits. HTTP 3xx/4xx/5xx become `ApiError`; its existing `code` remains
the numeric HTTP status, while `error_code` exposes a flat or nested API code.
Malformed/non-JSON error bodies remain available as text. Successful responses
with invalid JSON, unsupported content types or incompatible decoded model
values become `ResponseDecodeError`, retaining the response and native cause.
Transport and timeout failures also preserve Ruby's `cause`.
Premature end-of-body is a transport failure, even when the bytes received so
far happen to contain valid JSON.

The SDK selects `:net_http` independently of Faraday's process-wide default.
Explicitly installed custom middleware or a replacement adapter remains the
application's responsibility: it must preserve authentication, TLS validation,
deadlines and interruption cleanup, and must not retry or follow redirects
without an audited operation policy. Configure a client before sharing it;
do not mutate shared configuration during requests.

## Documentation for Authorization


Authentication schemes defined for the API:
### ApiKey


- **Type**: API key
- **API key parameter name**: X-API-Key
- **Location**: HTTP header

### McpIdentityToken

- **Type**: Bearer authentication


The service URL is fixed to https://api.reacon.io. SDKs do not accept a service URL override.

## Retrying requests

A timeout or dropped connection does not prove that the server rejected a request. Before retrying a write or credit-consuming operation, check its outcome. Only retry when the operation is safe to repeat; when present, respect the Retry-After response header. Keep application-level retries bounded as well: wrapping an SDK call in an unbounded retry loop can multiply requests and repeat side effects.

## Reporting failures

When reporting a failure, include the SDK package version and HTTP status. Include a request identifier if the response supplies one. Remove API keys and customer data from logs and bug reports. Redact Authorization and X-API-Key headers before sharing a request. Never include the API key in a URL or a screenshot.
